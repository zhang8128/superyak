# v2 stage 2, part 0: the instrument, row by row

Serenity, 2026-11-15 (UTC). Task 6, steps 3 and 4, of
`docs/superpowers/plans/2026-11-15-v2-stage-2-instrument.md`. The experiment is
`docs/superpowers/specs/2026-11-15-v2-stage-2-experiment.md`; this report goes down its table "How we know
part 0 is done" and says, for each row, what shows it and what does not.

**The decision: active seconds are the deciding outcome.** Tokens are not: a turn that the room ends at its
limit before its program has given a closing total has no whole token cost, for either program. Active
seconds are whole in every case of the table, for both programs. The decision does not change after this.

**Three rows are left unshown by decision, and each is said below with what stands in for it:** the offer
(not built; it is the second plan's), the record's ties (part in the store, part written beside each turn
by the pilot's script), and one clause about a worker's own commit holding a message file. What else the
evidence does not reach is in the table's last column and listed at the end. That list is longer than
these three.

**Two readers of the other model family read this before any pilot turn.** The first read the report, its
tests and the pilot's scripts and said: run the pilot after named changes. The second read those changes
and named three more. All are made, and said where they bear: a turn that is lost now stops the pilot, what
a turn is tied to is written down before it starts, and several sentences here say less than they did.

## What was run

- **The instrument:** the `v2` branch at the commit that adds this report. Its tests are run as CI runs
  them, on macOS 27 (arm64) and Debian (aarch64), on one tree compared by a single hash; CI adds Ubuntu
  x86-64. The counts are at the end.
- **Stand-ins, not models, for every row but one.** A stand-in is a script named `claude` or `codex`,
  first on the clock's search path. It prints a stream captured from that program and then does what the
  case says. The real clock runs it from the command line, and the test reads the turn's record from the
  store. These are `v2/crates/yak/tests/part0.rs`: twelve tests. Ten go down the table, each over both
  programs; two are of the tests' own cleanup.
- **What a stand-in cannot show:** how the real programs behave when they are ended, what they send a
  model, and what their own sandboxes do. It shows what the room does with what a program prints.
- **Live turns for one row,** "What a worker's shell can read": ten turns, each program once in five
  rooms. They cannot be stand-ins, because what is asked is what each program's own sandbox does.
- **Three live replays** of the first run's items, after all of the above, as the experiment's smoke
  test: can a worker still do real work under the rule that hides so much from its shell.

**That each test can fail** was shown by changing the room, one line at a time, and running `part0`:
fifteen changes, each still compiling, each failing the test of its own row. Among them: a record that
takes no tokens; a turn ended at its limit always marked as having no whole cost; a signal's end recorded
as an exit; a stop not recorded as one; changed files not recorded; names read back in the order of the
alphabet; a step that names nothing left out, with and without the count of steps seen; a check's time

## Tokens or seconds

The experiment's rule: tokens decide only if every row that speaks of a token cost shows a whole total, for
both programs. If any does not, active seconds decide.

- **A turn ended at its limit before its closing total has no whole total.** `part0` shows the record says
  so and makes none up. Measured before the build, once for each real program: ended by TERM in the middle
  of a shell command, as the room ends a turn at its limit, neither wrote a closing total.
- **So tokens are not the deciding outcome.** They are still recorded for every turn that gives them, in
  their parts, and are reported beside the seconds.
- **Active seconds are whole in every case:** normal, no tool call, failed, nothing handed in, limit, crash
  and kill, for both programs. In each, the parts of the record add up to its active time.

## What a worker's shell can read

Ten live turns through the clock, on macOS 27 (arm64), with Claude Code 2.1.325 (`claude:haiku`) and
codex-cli 0.163.0 (`codex:gpt-6.1-sol`): five rooms, each program once in each. The item's work is to run
a script of probes and commit what it prints. What each turn would print was written down before it ran,
and each printed that.

**A line that says CANNOT means that a command failed in the worker's shell.** That the failure is a
refusal, and not a target that was never there, rests on two things.

- **The same probe, run where nothing is hidden,** by the same user, against the same targets, reaches
  every one of them: 26 to 28 lines that say CAN and none that says CANNOT, for each of the five rooms. For
  the last two rooms this was done by the kit before its clock started, and a kit that fails it does not
  run. For the first three it was done some hours after their turns, with their targets as they had been
  left.
  One probe's target is the directory above wherever the probe runs, so for that one line the control is
  of another directory; the room's directory, which holds the sandboxes, is a target of its own.
- **In the last two rooms each failed command's last words were kept.** Of 20 failures in each program's
  shell, 17 said "Operation not permitted". Two were the earlier answer's objects, which a sandbox does
  not hold and git says nothing about. The last was the network: Codex's shell could not find the host by
  its name, and Claude's was refused with a 403 by what its sandbox routes the network through.

What the turns printed:

- **Used, in every turn:** a file in the sandbox, git in the sandbox, an object of the base, the named
  tool, the turn's own temporary directory, a compiler. Git and the compiler printed no complaint.
- **Failed, in every turn:** listing the directory that holds the sandboxes, the room's directory and its
  store, the item's repository (also through git, and through a link in a second tool directory), a file
  of another checkout, the home, both programs' own records of earlier sessions, the shell's history, a
  file left in the shared temporary directory, what an earlier turn left in a temporary directory of its
  own, `/tmp`, the machine's temporary directory, other processes, the network.
- **Absent from the sandbox:** the earlier answer's commit and file, as objects.
- **Instructions:** each program gave back the word planted in the repository's own instruction file when
  that file was of the kind it reads, and never a word planted above the room. In a room whose files are
  `CLAUDE.md`, Claude gave the repository's word and Codex gave none; in a room whose files are
  `AGENTS.md`, both gave the repository's word.
- **The search service shows little.** It found nothing holding the marker in any worker's shell. Where
  nothing is hidden it found the files hours later, and not within seconds of their making. So a worker's
  nothing may be the service's own delay.

**To run it again:** `v2/probes/reach/setup.sh` makes the item's repository and what an earlier turn would
have left; `v2/probes/reach/run.sh` adds the two probe items to a new room, runs the probe's control, and
runs the clock once through. Both say at their top what they read from the environment. The two checks are
`v2/checks/worker-reach-done.sh`, written by a Codex builder for the item a Claude worker takes, and
`v2/checks/worker-reach-done-claude.sh`, written by the lead for the item a Codex worker takes. A check
asks only that what was handed in ends as the probe's output ends and holds a line of each kind. A file
made up to look so would pass it; a person reads what was printed.

## What stands in for the ties

The experiment asks that everything a record is tied to be written and read back. The store holds what is
in the table above. For the pilot, which offers nothing and has no arms, the rest is written beside each
turn, before its clock starts, by `v2/probes/pilot/records.py`, as `manifest.json` in the turn's
directory:

- the clock's command, word for word, and apart from it every word of the environment it is given;
- the limits in force: the room program's own defaults, read from its help, and over them each one the
  command sets, with whether the turn has a first line of its own;
- the room program's path and SHA-256, and the worker's program as the clock will find it, with the
  version it says. A program that is not found, ends badly or says nothing refuses the turn;
- the item's base, its wrong commit, its check and the check file's blob;
- the turn's place in the plan, and the SHA-256 of the block's `versions.txt`.

Around the block, `v2/probes/block-check.sh` looks for instruction files where a program would load them
by itself, writes down both programs' versions, git's, the room program's hash and the machine, and at the
block's end refuses a block in which any of that changed. Each is asked by itself, and its answer must be
one: an earlier form of the script would have written down a failed question as if it were a version, and
the form after that still took a hash tool's complaint for a hash. A digest is 64 hex digits from a tool
that ended well.

The arm, the seed and the run belong to the second plan, with the offer, and must be in the store before
part 3. This is a decision of the lead's. The reader held that a file beside the turn is enough for a
pilot with no arms, once it holds the command and the limits, which it did not until they said so.

## What keeps a lost turn from going unseen

The pilot is `v2/probes/pilot/pilot.sh`: 21 turns in an order it writes down before the first, each one run
of `turn.sh` in a room of its own with a new copy of the items' repository.

- **Each turn must leave one usable observation,** or its script fails and the pilot ends there: one
  attempt, taken by the worker that was planned, whose program ran to an end of its own or to its limit,
  with a verdict, and a record whose parts add up. A turn that failed its check or ran its twenty minutes
  is one. A turn that did not run, a clock that died, two attempts, and a record that is missing are not.
- **The tables are printed only for a whole pilot:** every turn of the plan once, no directory the plan
  does not have, both block checks ended well. For a pilot that stopped they are printed only when asked
  for as partial, under a list of what is missing. The worker printed is the one the record names.
- **The reader's first finding was that none of this was so:** the first form of the tables listed
  whatever directories were there, so a lost turn vanished and a second attempt counted as another turn.
- **Tested** by `v2/probes/pilot/test_records.py`, 27 tests with no model and no clock: records made by
  hand, and both of the pilot's own scripts run with scripts in place of the room program and the workers.
  A turn whose script fails ends the pilot before the next; a record that is not usable fails the turn's
  script. Sixty changes to the four scripts, one line each, each fail a test.
- **Rehearsed** twice with stand-ins that do nothing, nine turns each, and once with a stop after the
  first turn. The first rehearsal found that a clock ending with something other than 0 left its exit
  unwritten; the second ran the plan's order with a manifest and a check for every turn.

## What is not shown, in one place

- **Linux.** Every measurement of what a worker's shell can read is from one Mac. The tests run on Linux;
  the two programs' own sandboxes there are not measured.
- **What the real programs do when ended, and what they send.** The stand-ins show the room's side.
- **Text of a turn that was somewhere for a while.** The scan is of the room's directory after the turn.
  It does not see a file since removed, a file outside the room, text that was encoded, or what a
  worker's program or its provider keeps.
- **That every later turn of the pilot finds its program's memory warm.** One turn of each worker is
  thrown away first; after that the gaps are recorded, not bounded.
- **The offer.** Not built.
- **The ties** not in the store, above.
- **A worker's own commit that holds a file named as the message file:** no test.
- **Added and removed files** through a stand-in of each program: shown with a script worker only.
- **A real model's token counts against what its provider charges.** The record holds what the program
  printed.
- **A sign-in-only home for the worker programs.** Until a person decides it, a worker's program can read
  its own home; its shell cannot.
- **Whether a sandbox's path alone already separates two turns in a program's memory.** Each turn's sandbox
  has a path of its own, and both programs tell the model its working directory before the room's prompt
  begins. So a first line of the turn's own may measure as changing nothing, as the ship Tardis pointed out
  on reading the switch. The room gives no two turns one path, so the pilot's memory test cannot tell the
  path from the line. The line is kept either way.
