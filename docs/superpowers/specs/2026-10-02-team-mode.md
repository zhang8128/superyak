# Team mode in Superyak

User request: "can you combine this with superyak and make it built in for there?" — team mode
(built in loom as codex-pair 6.0–6.2) becomes a first-class Superyak component.

## Design
- `team/` component, stdlib only, own `pyproject.toml`/`uv.lock`, package `superyak_team`, single
  launcher `team/run_team.py` used by `superyak-runtime team`, the team daemon and every worker's
  MCP server (pinned interpreter, no PYTHONPATH; `runtime.py` keeps its file-target check).
- Exposure: Claude Code via the engram plugin (`.mcp.json` server `team`, `/engram:team`,
  `skills/team`); Codex via `[mcp_servers.team]` and the `superyak-team` skill. Both route
  through `superyak-runtime team`, like engram's server and hooks.
- Names: `SUPERYAK_TEAM_*` env, `~/.superyak/team/` state, Keychain `superyak-team` and
  `superyak-team-slack-bot`, sockets `/tmp/sy-team-<uid>/`. Renamed while no team was running and
  before any Slack token existed; the codex-pair master key was deleted.
- Scope: developer-agent orchestration only (see docs/team-mode.md); not the pilot research pool.

## Verified constraints (do not "fix" these away)
- Codex workspace-write protects every `.git`, even with `--add-dir`; never set `writable_roots`.
- Only `-c mcp_servers.X.enabled=false` for `[mcp_servers.X]` tables; plugin servers break config
  loading ("invalid transport") — plugins are disabled via `plugins."name".enabled=false`.
- Codex web search is on by default; workers set `web_search="disabled"`.
- A CLI `--permission-mode` overrides the settings file; Claude permission paths need `//` for
  absolute paths; sandbox deny globs win over `allowRead`.
- engram's `load_config` writes `.engram/config.toml` into its project root when missing; teamd
  seeds the worker folder once at spawn with O_NOFOLLOW/O_EXCL (teamd is unsandboxed, so it must
  never write through a worker-planted symlink).
- Slack mirroring is opt-in per repo (`slack_repos`, `.superyak-team-local-only`).
- teamd's own git calls in a worker folder use the git dir recorded at spawn
  (`--git-dir/--work-tree`), with hooks, fsmonitor and untracked cache off and `--no-verify`;
  a worker-rewritten `.git` pointer once let a hook run as the user (reproduced, then fixed).
  It also runs without user/system git config and blanks every filter/diff/merge driver in the
  repo config: a worker's `.gitattributes` could otherwise trigger them (e.g. a global git-lfs
  filter). Side effect: teamd's commits do not run LFS clean filters.
- Prompts are the last argv element and never start with `-` (`workers.safe_prompt`).
- No worker sandbox can connect to a Unix socket (Codex workspace-write and read-only, Claude
  sandbox: `Operation not permitted`, verified 2026-10-02). That is what makes the split-key
  tokens sufficient even if two workers of different kinds pooled the halves: only the
  unsandboxed team MCP servers, whose identity teamd fixes, can reach teamd. Do not grant
  workers `allowUnixSockets`/`allowAllUnixSockets` or Codex network access.
