# v2 Stage 1: The Room Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One Rust binary, `yak`, that runs turns on real work with frozen checks and no keystrokes, and leaves a
ledger and whole walks behind.

**Architecture:** A library crate `room` owns the state machine and the SQLite store, with one writer. A library
crate `turn` runs one turn: a sandbox, a worker, a frozen check. The binary `yak` holds the clock loop, the CLI
and a read-only MCP server. A turn's only effect is a commit on its own branch; the clock is the only thing that
acts.

**Tech Stack:** Rust stable 1.100.0 (the Pi's), `rusqlite` with bundled SQLite, `clap`, `serde`, `sha2`,
`thiserror`, `rand`, the official Rust MCP SDK `rmcp`, `tempfile` and `assert_cmd` in tests. Check each crate's current
documentation before pinning a version.

**Spec:** `docs/superpowers/specs/2026-11-14-superyak-v2-design.md` (draft 3). Sections 6 to 9 and 11 bind this
plan.

**Who builds what.** The spec's own rule is that a check is never the worker's. So:

| Who | Tasks |
| --- | --- |
| Tardis | Task 0: the acceptance suite and CI, written first and frozen before the builders start |
| Sol (Codex) | Tasks 1 to 5 and 10: the `room` crate, the CLI and MCP |
| Opus (Claude) | Tasks 6 to 9: the `turn` crate and the clock |
| The lead | Task 11: the real run and its report |

Opus reads Sol's branches and Sol reads Opus's, before either merges into `v2`.

## Global Constraints

- All work lands on branch `v2` under `v2/`. Nothing merges to `main` in this plan.
- The repository is public. No private name, research detail, prompt text or transcript text in any tracked file.
- No `unsafe`. No dependency on v1's Python.
- Builds and passes on macOS arm64, Linux aarch64 (the Pi) and Linux x86_64.
- The store is `room.sqlite3`, write-ahead log, `synchronous=FULL`, on local disk, one writer.
- A missing or damaged store is refused with a message. Only `yak init` creates one.
- The store holds no text from a transcript or a prompt (spec rule 9). `Step` has no free-text field.
- A turn cannot post, push or pay. Its sandbox is a local clone with no remote.
- The values in `crates/room/src/limits.rs` are fixed here:

  | Constant | Value |
  | --- | --- |
  | `LEASE_SECS` | 1800 |
  | `TURN_SECS` | 1200 |
  | `TERM_GRACE_SECS` | 10 |
  | `MAX_ATTEMPTS` | 3 |
  | `DAILY_TURNS` | 40 |
  | `CONCURRENT_TURNS` | 1 |
  | `CHECK_TIMEOUT_SECS` | 900 |
  | `RECHECK_ONE_IN` | 5 |
  | `CLOCK_POLL_SECS` | 5 |
  | `SCHEMA_VERSION` | 1 |

- The room directory defaults to `~/.superyak/v2/room` and holds `room.sqlite3`, `LOCK`, `STOP` (when stopped),
  `checks/<check_hash>/` and `turns/<attempt>/`.
- A turn's sandbox and its raw transcript are deleted once its steps and verdict are recorded.
- A team builder does not run `git commit`: the team's daemon commits its work when it reports done. Where a
  task below says "Commit", a team builder instead notes which files belong to that task. Anyone else commits per
  task, with a message ending `Made by <worker>.`
- **Builders have no network.** The lead set up the workspace, `Cargo.lock`, `crates/room/src/types.rs` and
  `limits.rs`, and vendored every crate outside the repository. Start with `sh v2/scripts/offline.sh` from the
  repository root, then `export PATH="$HOME/.cargo/bin:$PATH"`, and build with `cargo ... --offline` under `v2/`.
  A builder that needs a crate that is not vendored asks the lead and does not work around it.
- Do not change `types.rs` or `limits.rs`. If a signature in this plan cannot work, tell the lead.

## Review Focus

Inputs the spec implies and no builder would think to try first. Each has its test in the task named.

1. **The clock dies mid-turn** (power loss, `kill -9`). On restart the item is taken again with the next lease
   number, and the dead turn's late hand-in is refused. Task 3 and Task 0.
2. **A check that never ends.** It is killed at its timeout, the verdict says timed out, the item is not stuck.
   Task 7.
3. **A worker that edits or deletes the check's files.** The frozen copies judge it anyway. Task 7.
4. **Two clocks on one room.** The second refuses to start. Task 1.
5. **A store that is missing, damaged, or from a newer version.** Refused with a message; never replaced by an
   empty one. Task 1.

## Shared Types

Defined once in `crates/room/src/types.rs` by Task 1. Every later task uses these names exactly.

```rust
pub type Ts = i64; // seconds since the Unix epoch, UTC

pub struct ItemId(pub String);    // "i" + 12 lowercase hex
pub struct AttemptId(pub String); // "a" + 12 lowercase hex

pub enum ItemState { Draft, Open, Leased, Checking, PassedVerified, PassedUnverified, Failed, Blocked, Abandoned }
pub enum CheckOrigin { Outside, ObservedFailure, Model }

pub struct CheckSpec {
    pub command: String,              // run with `sh -c` at the repository root
    pub files: Vec<String>,           // tracked paths the check reads; frozen by content
    pub timeout_secs: u32,
    pub origin: CheckOrigin,
    pub wrong_artifacts: Vec<String>, // commits the check must fail on
    pub written_by: String,           // "person:<name>", "ship:<name>", "claude:<model>", "codex:<model>"
}
pub struct NewItem { pub title: String, pub repo: PathBuf, pub base_commit: String, pub after: Vec<ItemId>, pub check: CheckSpec }
pub struct Frozen { pub check_hash: String, pub red_on_base: bool, pub red_on_wrong: Vec<bool> }
pub struct Lease { pub item: ItemId, pub attempt: AttemptId, pub lease_no: u32, pub worker: String, pub expires: Ts }
pub struct Verdict { pub passed: bool, pub exit_code: i32, pub timed_out: bool, pub commit: String, pub check_hash: String, pub output_sha256: String }

pub enum Tool { Read, Edit, Write, Search, Shell, Other }
pub enum Target { TrackedFile { path: String, blob: String }, Outside }
pub struct Step { pub seq: u32, pub tool: Tool, pub target: Target, pub ok: bool, pub tokens_in: Option<u32>, pub tokens_out: Option<u32> }

pub enum DisagreementKind { RecheckDiffers, Abandoned, WeakCheck }
pub struct Disagreement { pub kind: DisagreementKind, pub item: ItemId, pub detail: String }

pub enum RoomError {
    Missing(PathBuf), Damaged(String), NewerSchema { found: u32, known: u32 }, Locked,
    Stale { lease_no: u32, current: u32 }, NotTakeable(String),
    Ceiling { used: u32, limit: u32 }, Stopped, Refused(String), Db(String),
}
```

A worker's family is the part of its name before the colon.

**What landed, 2026-11-14.** Three things, each a rule later tasks and their tests must fit.

*The jail* (`turn::jail`, `Sandbox::run_untrusted`). A check, a script worker and the room's own git in a
worker's tree run inside an OS jail: `sandbox-exec` on macOS, `bwrap` on Linux. With neither, the run is refused;
nothing falls back to running unjailed. A model worker (`claude:`, `codex:`) is not jailed by the room: it uses
`run`, and keeps its own program's limits.

| A jailed run | |
| --- | --- |
| Writes | Only its checkout and a scratch directory beside the sandbox (`<sandbox>.scratch`), which is its `HOME` and `TMPDIR` and is removed with the sandbox |
| Reads and runs | Only the system's programs and libraries, its checkout, its scratch directory, a script worker's own program file, and each path in `YAK_JAIL_READ` |
| Asks about | Itself. Not other processes: not their names, their paths, their arguments or their environment |
| Makes | On Linux, internet sockets on its own empty network, netlink for routes, and a Unix stream pair. No other socket, and no call that reaches the keyring |
| Never sees | A home directory, the shared temporary directories, other disks; the home's keys and tokens and the directories `CLAUDE_CONFIG_DIR` and `CODEX_HOME` name, even inside something shown |
| Network, signals, services | None; it signals only what is in the same jail |

- `YAK_JAIL_READ` is a colon-separated list, for a toolchain outside the system directories. An entry that is
  relative, is not there, holds the home directory, is hidden, or holds a place where keys or settings are kept
  (whether or not anything is there yet) is refused, as is a worker program kept in a hidden place. Such a
  place is known by every road to it: its name as written, and its name with the links on the way to it
  followed, the first of them, the first two, and so on. So a directory that is a link is refused like the
  directory it leads to, and so is a directory that holds a link to such a place, since a link can be replaced
  by a directory later. A link is followed by what it says, whether or not anything is there yet: a directory
  made later where it points is where the name would land. A name below a part that is not there is kept as
  written, and the walk still looks at every name after it, since a `..` can lead back out onto a link. A
  link whose remaining words would climb back out of it, were it a directory, has no place the jail can give:
  no jail starts beside a protected name laid out like that. A name that is there is taken as the machine
  spells it: on a disk where capital and small letters name the same file, a directory kept as `.Cargo` is
  where `.cargo` leads. On macOS the jail's own rules do not tell capital letters from small (measured on
  macOS 27: a rule written `share` shows a directory kept as `SHARE`, and the other way round), so there every
  comparison of such a place with a shown directory ignores them, also for a name that is not there yet and
  has no spelling but the one written. Ignoring letters only ever finds more places to refuse. The one
  comparison that lets a place through (it lies in a path that is there and hidden) is made with the letters
  as they are. A protected name behind a ring of links cannot be placed, and no jail starts beside
  it. The same rule holds for the directories every run is shown without
  their being named, judged by their names and by where their names lead: if such a place would lie in one of
  them, or one of them in such a place, and it is not there yet, no jail starts; if it is there, it is hidden
  where it is, with whatever is put in it later. Where a directory's name leads somewhere else, hiding a place
  by its own name does not hide it under that directory's, so there the jail does not start at all. Nothing named is silently left out. So a
  toolchain is named by its own directory (`~/.cargo/bin`), not by one above it.
- The jail does not start without a `HOME` that is the full path of a directory that exists: it keeps a home
  out by knowing where it is.
- `YAK_JAIL=off` turns the jail off. It exists for tests that run inside another sandbox, where no jail can be
  entered. `yak clock run` refuses it when any worker is a model.
- **For every test from here on:** it must hold with the jail on. A script or a check never writes beside the
  room or reads a file beside its script. Evidence comes from the room, from the commit the turn handed in, or
  from the pid file. A builder's sandbox cannot enter a jail, so a builder runs its tests with `YAK_JAIL=off`
  and the lead runs them on the host.
- Run on macOS 27 and on Debian (aarch64, the Pi).

*Process supervision* (`turn::process`). A run has a record, `turns/<attempt>.pid` for a worker and
`turns/<attempt>.check.pid` for its check. Its first line is the process group and its second the leader's
start time; each line after names one more process the run was seen to start, as its number, a space and its
start time. A number and a start time together say whose process it is, so a number that has gone to another
process is never signalled. A run's descendants are watched every 200 ms and ended with it, also those that
left its group; the record is written anew whenever a process is seen for the first time, or a number is seen
to belong to another process than the one recorded under it. `YAK_SUPERVISION=best-effort` lets a run start where processes cannot be listed; the clock
refuses it when any worker is a model. Known limit: on macOS a descendant that detaches while its parent exits
between two looks can be missed.

*After a clock dies.* The next clock ends each run a record describes: the leader and every process the record
names that is still the process it was, whether or not the leader is among them. It acts only on a record
named for an attempt the room made. If a run cannot be ended, the clock stops and names the record: that run's
record and directories stay as they are, and no directory of any run is removed. The records of runs it had
already ended by then are gone, each removed as its run was known to be over.

*A run that cannot be confirmed ended.* A run is over when the room has seen that every process it started is
gone. When that cannot be seen (the processes cannot be listed, or one will not go), the run's record is kept
and the error says so (`TurnError::Unended`). This holds for a worker's run, a check's and a freeze's. The
clock then stops (`ClockError::Unrecovered`) before it removes the run's sandbox or tidies the turn, and
starts no other turn; a clock started again finds the record and stops in the same way until the run is
ended. This comes before a failure of the room's store in the same turn: a store that fails ends the clock,
and is no leave to remove what is left of a run that may still be going. The clock stops for the run and says
that the store failed as well.

*What a removal leaves.* A sandbox and its scratch directory are removed only if each is still the directory
the room made there. Anything else found at either path, also a scratch directory the room never made, is left
as it is, and the error names the paths (`TurnError::Left`). A check or a freeze that finds such a thing in its
work directory leaves that directory too, and so does the clock's tidying after the turn. No verdict is taken
from a check whose sandbox was replaced. What was left is said before anything else that went wrong in the
same step, with that beside it: a check that failed for a reason of its own, a removal that failed, or the
room's store failing meanwhile. It is remembered under every name the disk has for it. On a disk where
capital and small letters name the same file that need not be how the room would have written it, and a file
can have more than one name in a directory.

*Whom this holds.* A check, a script worker and the room's git in a worker's tree are held by the jail. A model
worker is held by its own program's sandbox, which the room sets to let it write in its clone and nowhere else
of the room's. The room's own files are safe from a model worker only as far as that sandbox holds.

*Known limits, accepted for stage 1.* A check is not ended by the stop file, only by its own time limit. On
Linux a jailed run can still make a user namespace of its own, and the filter refuses named calls and is not a
list of every call allowed. The x86-64 form of the filter has run only in the test that interprets it. Which
directory a sandbox is, is looked at before each run and before removal, and is not held still during a run by
anything but the jail. A jailed run can read the machine's name and learn that a directory above its checkout
exists. What a removal left in place stays only until the next clock starts, which removes what is in `turns/`
by where it is. The turn's ref is the turn's only if its name was free when the clock came to make it, and
nothing else is taken to write `refs/heads/room/` in the item's repository while the clock runs. A hand-in
that the room refuses just after the ref was made leaves the ref. Two names that differ only in how an
accented letter is put together are not taken as one when a protected place that is not there yet is compared
with a shown directory.

*A way to stop a sandbox* (`Sandbox::stop_switch`). Another thread sets it; the run in progress is ended as one
out of time is, and no later run starts in that sandbox.
