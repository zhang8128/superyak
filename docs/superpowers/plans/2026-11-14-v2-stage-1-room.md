# v2 Stage 1: The Room Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One Rust binary, `yak`, that runs turns on real work with frozen checks and no keystrokes, and leaves a
ledger and whole walks behind.

**Architecture:** A library crate `room` owns the state machine and the SQLite store, with one writer. A library
crate `turn` runs one turn: a sandbox, a worker, a frozen check. The binary `yak` holds the clock loop, the CLI
and a read-only MCP server. A turn's only effect is a commit on its own branch; the clock is the only thing that
acts.

**Tech Stack:** Rust stable 1.100.0 (the Pi's), `rusqlite` with bundled SQLite, `clap`, `serde`, `sha2`,
`thiserror`, `rand`, the official Rust MCP SDK `rmcp`, `tempfile` and `assert_cmd` in tests. Check each crate's current
documentation before pinning a version.

**Spec:** `docs/superpowers/specs/2026-11-14-superyak-v2-design.md` (draft 3). Sections 6 to 9 and 11 bind this
plan.

**Who builds what.** The spec's own rule is that a check is never the worker's. So:

| Who | Tasks |
| --- | --- |
| Tardis | Task 0: the acceptance suite and CI, written first and frozen before the builders start |
| Sol (Codex) | Tasks 1 to 5 and 10: the `room` crate, the CLI and MCP |
| Opus (Claude) | Tasks 6 to 9: the `turn` crate and the clock |
| The lead | Task 11: the real run and its report |

Opus reads Sol's branches and Sol reads Opus's, before either merges into `v2`.

## Global Constraints

- All work lands on branch `v2` under `v2/`. Nothing merges to `main` in this plan.
- The repository is public. No private name, research detail, prompt text or transcript text in any tracked file.
- No `unsafe`. No dependency on v1's Python.
- Builds and passes on macOS arm64, Linux aarch64 (the Pi) and Linux x86_64.
- The store is `room.sqlite3`, write-ahead log, `synchronous=FULL`, on local disk, one writer.
- A missing or damaged store is refused with a message. Only `yak init` creates one.
- The store holds no text from a transcript or a prompt (spec rule 9). `Step` has no free-text field.
- A turn cannot post, push or pay. Its sandbox is a local clone with no remote.
- The values in `crates/room/src/limits.rs` are fixed here:

  | Constant | Value |
  | --- | --- |
  | `LEASE_SECS` | 1800 |
  | `TURN_SECS` | 1200 |
  | `TERM_GRACE_SECS` | 10 |
  | `MAX_ATTEMPTS` | 3 |
  | `DAILY_TURNS` | 40 |
  | `CONCURRENT_TURNS` | 1 |
  | `CHECK_TIMEOUT_SECS` | 900 |
  | `RECHECK_ONE_IN` | 5 |
  | `CLOCK_POLL_SECS` | 5 |
  | `SCHEMA_VERSION` | 1 |

- The room directory defaults to `~/.superyak/v2/room` and holds `room.sqlite3`, `LOCK`, `STOP` (when stopped),
  `checks/<check_hash>/` and `turns/<attempt>/`.
- A turn's sandbox and its raw transcript are deleted once its steps and verdict are recorded.
- Commit messages end with `Made by <worker>.` and the worker's co-author line.
- **Builders have no network.** The lead set up the workspace, `Cargo.lock`, `crates/room/src/types.rs` and
  `limits.rs`, and vendored every crate outside the repository. Start with `sh v2/scripts/offline.sh` from the
  repository root, then `export PATH="$HOME/.cargo/bin:$PATH"`, and build with `cargo ... --offline` under `v2/`.
  A builder that needs a crate that is not vendored asks the lead and does not work around it.
- Do not change `types.rs` or `limits.rs`. If a signature in this plan cannot work, tell the lead.

## Review Focus

Inputs the spec implies and no builder would think to try first. Each has its test in the task named.

1. **The clock dies mid-turn** (power loss, `kill -9`). On restart the item is taken again with the next lease
   number, and the dead turn's late hand-in is refused. Task 3 and Task 0.
2. **A check that never ends.** It is killed at its timeout, the verdict says timed out, the item is not stuck.
   Task 7.
3. **A worker that edits or deletes the check's files.** The frozen copies judge it anyway. Task 7.
4. **Two clocks on one room.** The second refuses to start. Task 1.
5. **A store that is missing, damaged, or from a newer version.** Refused with a message; never replaced by an
   empty one. Task 1.

## Shared Types

Defined once in `crates/room/src/types.rs` by Task 1. Every later task uses these names exactly.

```rust
pub type Ts = i64; // seconds since the Unix epoch, UTC

pub struct ItemId(pub String);    // "i" + 12 lowercase hex
pub struct AttemptId(pub String); // "a" + 12 lowercase hex

pub enum ItemState { Draft, Open, Leased, Checking, PassedVerified, PassedUnverified, Failed, Blocked, Abandoned }
pub enum CheckOrigin { Outside, ObservedFailure, Model }

pub struct CheckSpec {
    pub command: String,              // run with `sh -c` at the repository root
    pub files: Vec<String>,           // tracked paths the check reads; frozen by content
    pub timeout_secs: u32,
    pub origin: CheckOrigin,
    pub wrong_artifacts: Vec<String>, // commits the check must fail on
    pub written_by: String,           // "person:<name>", "ship:<name>", "claude:<model>", "codex:<model>"
}
pub struct NewItem { pub title: String, pub repo: PathBuf, pub base_commit: String, pub after: Vec<ItemId>, pub check: CheckSpec }
pub struct Frozen { pub check_hash: String, pub red_on_base: bool, pub red_on_wrong: Vec<bool> }
pub struct Lease { pub item: ItemId, pub attempt: AttemptId, pub lease_no: u32, pub worker: String, pub expires: Ts }
pub struct Verdict { pub passed: bool, pub exit_code: i32, pub timed_out: bool, pub commit: String, pub check_hash: String, pub output_sha256: String }

pub enum Tool { Read, Edit, Write, Search, Shell, Other }
pub enum Target { TrackedFile { path: String, blob: String }, Outside }
pub struct Step { pub seq: u32, pub tool: Tool, pub target: Target, pub ok: bool, pub tokens_in: Option<u32>, pub tokens_out: Option<u32> }

pub enum DisagreementKind { RecheckDiffers, Abandoned, WeakCheck }
pub struct Disagreement { pub kind: DisagreementKind, pub item: ItemId, pub detail: String }

pub enum RoomError {
    Missing(PathBuf), Damaged(String), NewerSchema { found: u32, known: u32 }, Locked,
    Stale { lease_no: u32, current: u32 }, NotTakeable(String),
    Ceiling { used: u32, limit: u32 }, Stopped, Refused(String), Db(String),
}
```

A worker's family is the part of its name before the colon.

| `stop_halts_within_fifteen_seconds` | Creating `STOP` ends every worker process and no new turn starts |
| `the_ceiling_refuses_the_next_turn` | With the daily ceiling set to 2, a third dispatch is refused and says so |
| `a_worker_cannot_change_its_check` | A worker that rewrites the check's file to `exit 0` is still judged by the frozen copy |
| `a_worker_has_no_remote` | `git push` inside a turn fails, and the item's repository has no new remote ref |
| `no_prompt_text_reaches_the_store` | A worker stream carrying a marker string leaves no such bytes in `room.sqlite3` |
| `a_second_clock_refuses` | A second `yak clock run` on the same room exits non-zero and says locked |
| `a_missing_store_is_not_created` | `yak status` on an empty directory exits non-zero and creates no file |

### Task 9: The clock (Opus)

**Files:**
- Create: `v2/crates/yak/{Cargo.toml,src/clock.rs}`
- Test: `v2/crates/yak/tests/clock.rs`

**Interfaces:**
- Consumes: Tasks 1 to 8.
- Produces: `clock::run(room: &mut Room, workers: &[String], mode: Mode, rng: &mut dyn RngCore) -> Result<(), ClockError>`
  with `Mode::{Forever, OnceThrough}`; `clock::freeze_drafts(room: &mut Room) -> Result<u32, ClockError>`.

One pass of the loop, in this order: stop if `room.stopped()`; `expire_due`; `freeze_drafts`; `take` for the next
worker in turn; create the sandbox; run the worker, renewing the lease every 300 seconds; `hand_in`; fetch the
sandbox's branch into the item's repository as `refs/heads/room/<item>/<lease_no>`; `run_check`;
`record_verdict` with `classify`; `record_walk`; destroy the sandbox. That fetch is the only effect outside the
room's directory. With probability one in `RECHECK_ONE_IN`, a verified pass is checked again in a fresh clone,
and a differing verdict makes the item `PassedUnverified` with a `RecheckDiffers` disagreement.

## What stage 1 leaves out, on purpose

- `lay`, `who`, `pull`, `route`, `connect`, `compare`, and the hook. Stages 3 and 4.
- Any tool that lets a session write to the room over MCP.
- Posting to the station or pushing a branch. The clock's one effect is a local ref.
- Reading the board. Items are added by command in this stage.
- An "outcome unknown" state. The one effect in this stage is a local fetch, which can be repeated safely.
