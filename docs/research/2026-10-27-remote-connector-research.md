# Remote connector research (fetched 2026-10-27; public pages only)

## 1. Claude custom connectors (remote MCP)
- **Transport:** use Streamable HTTP; legacy HTTP+SSE still works but "is being deprecated". A URL ending `/sse` selects SSE. https://claude.com/docs/connectors/building/index.md ; https://claude.com/docs/connectors/custom/add-unlisted.md
- **Plans:** custom connectors by URL work on Free (one connector), Pro, Max, Team, Enterprise. Team: Owners add, members then "Connect" with their own account. Enterprise: Owners or custom role with Libraries access. https://claude.com/docs/connectors/custom/add-unlisted.md ; https://support.claude.com/en/articles/11175166-getting-started-with-custom-connectors-using-remote-mcp
- **Mobile:** same connector infrastructure backs claude.ai, Desktop, mobile, Cowork, Claude Code. Connectors are configured on the account and work in mobile apps. https://claude.com/docs/connectors/building/authentication.md ; support article 11175166 above. (Not verified: whether adding a connector can be done from the phone UI; docs only say it works there once added.)
- **Auth:** OAuth per user (own sign-in), static headers (beta, limited orgs), or none. Follows MCP auth specs 2025-03-26, 2025-06-18, 2025-11-25. Newer spec 2026-07-28 exists (https://modelcontextprotocol.io/docs/tutorials/security/authorization); Claude's docs do not list it, so not confirmed supported. https://claude.com/docs/connectors/building/index.md
- **Must implement:** (a) unauthenticated request returns **401** with `WWW-Authenticate: Bearer resource_metadata="https://host/.well-known/oauth-protected-resource"`; Claude ignores that header on a 200. (b) RFC 9728 protected-resource JSON whose `resource` equals the URL the user typed exactly (including path) and whose first `authorization_servers` entry is used (no fallback). (c) RFC 8414 `/.well-known/oauth-authorization-server` or OIDC `/.well-known/openid-configuration` (tries the former first). (d) PKCE S256 on every request; advertise `code_challenge_methods_supported: ["S256"]`. (e) Client registration: DCR (`registration_endpoint`) or CIMD (needs `client_id_metadata_document_supported: true` AND `"none"` in `token_endpoint_auth_methods_supported`, else falls back to DCR), or user-entered client ID. (f) `/token` accepts `application/x-www-form-urlencoded`; Claude sends RFC 8707 `resource` (lowercase scheme/host, no trailing slash). (g) Rotate refresh tokens for public clients; return `invalid_grant` on bad refresh; Claude refreshes on 401 and up to 5 min before expiry; adds `offline_access` if listed in `scopes_supported`. (h) Timeouts: 10 s for discovery/registration/token, 30 s for refresh. https://claude.com/docs/connectors/building/authentication.md
- **Callback to allow-list:** `https://claude.ai/api/mcp/auth_callback` (web, Desktop, mobile, Cowork). Claude Code uses loopback `http://localhost/callback` / `127.0.0.1` on any port. Older help text warned it may later move to claude.com; current docs list only claude.ai. https://claude.com/docs/connectors/building/authentication.md ; https://support.claude.com/en/articles/11503834
- **Egress IPs:** outbound MCP calls come from **160.79.104.0/21 (IPv4 only)**; old 34.162.x addresses retired. Applies to the authorization server too. https://platform.claude.com/docs/en/api/ip-addresses
- **Annotations:** docs require `title` plus `readOnlyHint: true` (read-only) or `destructiveHint: true`; "These determine auto-permissions": read-only tools can run without per-call confirmation, destructive always prompt (stated in the directory checklist; we assume custom connectors behave the same, not explicitly stated). Users can also set per-tool Blocked / Always allow. https://claude.com/docs/connectors/building/review-criteria.md ; https://claude.com/docs/connectors/custom/add-unlisted.md
- **Limits:** ~150,000 chars per tool result; 240 s per tool call on claude.ai/Desktop. Names at most 64 chars. Sampling and resource subscriptions unsupported. https://claude.com/docs/connectors/building/index.md

## 2. ChatGPT
- **Where:** chatgpt.com/plugins, plus button, "Add custom MCP server" (public URL ending `/mcp`, or a Tunnel), set auth, accept risk warning, "Create as a plugin". "Refresh" re-reads the tool list. Note 2026 renaming: "apps" became "plugins" in this doc. https://developers.openai.com/apps-sdk/deploy/connect-chatgpt
- **Plans (UNRESOLVED):** OpenAI's help article (which I could not fetch, HTTP 403) is reported to say Apps/full MCP/developer mode are for Business and Enterprise/Edu on web, with write actions in beta, and creation/publishing limited to admins/owners. Third-party pages conflict on Plus/Pro (some say read-only custom connectors work on Plus/Pro, some say not at all); Free cannot add custom servers. Treat Plus/Pro as unknown; test with a real account. https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt-beta (secondary summary only); https://coworker.ai/blog/chatgpt-mcp ; https://peliqan.io/blog/chatgpt-mcp/
- **Auth (official):** OAuth with PKCE S256 required; protected-resource metadata + AS metadata; client registration via CIMD (preferred; `https://chatgpt.com/oauth/client.json`), or DCR, or predefined; sends `resource` param (copy into `aud`); redirect URIs to allow-list: `https://chatgpt.com/connector_platform_oauth_redirect` (if RFC 9207 `iss` supported) else `https://chatgpt.com/connector/oauth/{callback_id}` (copy exact value from the management page). Not supported: client credentials, service accounts, custom API keys. Optional mTLS client cert from OpenAI. https://developers.openai.com/apps-sdk/build/auth
- **Tool shape:** deep research / company knowledge need two read-only tools: `search(query)` returning `{results:[{id,title,url}]}` and `fetch(id)` returning `{id,title,text,url}`, each as `structuredContent` plus JSON text in `content`. Citations only appear if `url` is non-empty. https://developers.openai.com/api/docs/mcp
- **Writes:** allowed only where full MCP (beta) is enabled (Business/Enterprise/Edu per above). Web app only per third-party sources (mobile not stated by OpenAI).
- **Limits:** none stated officially.

## 3. Data handling
- **Claude Free/Pro/Max:** training on chats and Claude Code sessions depends on the "model improvement" setting; opt-out/in is in Privacy Settings; already-used data is not removed; 30-day retention if not allowed, up to 5 years if allowed; incognito chats never used. Pricing page lists consumer as "Opt-out". Whether the toggle defaults on today is NOT confirmed from a primary page (mixed sources). Whether tool/connector results count as chat content is not stated. https://privacy.claude.com/en/articles/12109829-how-do-i-change-my-model-improvement-privacy-settings ; https://www.anthropic.com/news/updates-to-our-consumer-terms ; https://support.claude.com/en/articles/8325621 (dated May 22, 2026). Safety-flagged conversations can still be used even after opt-out.
- **Claude Team/Enterprise:** "None by default" for training (pricing page; commercial terms). https://anthropic.com/pricing ; https://docs.anthropic.com/en/docs/claude-code/data-usage
- **Claude HIPAA:** BAA only for Enterprise after the Primary Owner enables "HIPAA-ready" and accepts it, and API. Free/Pro/Max/Team excluded. **The BAA explicitly does not cover connectors, including custom connectors, or local MCP servers**, even when enabled. https://support.claude.com/en/articles/8114513-business-associate-agreements-baa-for-commercial-customers
- **ChatGPT Free/Plus/Pro:** "Improve the model for everyone" on by default; off in Settings > Data controls (or privacy portal "Do not train on my content"); thumbs feedback can make the whole conversation trainable anyway. https://help.openai.com/en/articles/7730893-data-controls-in-chatgpt ; https://help.openai.com/en/articles/5722486-how-your-data-is-used-to-improve-model-performance (via search snippets; pages returned 403 to fetch). Not stated whether connector/tool output is covered.
- **ChatGPT Business/Enterprise/Edu:** no training on inputs/outputs by default. Same sources.
- **ChatGPT BAA:** Enterprise/Edu sales-managed only (also Healthcare/Clinicians products); not Business; PHI barred from uncovered features. I could not confirm whether apps/MCP connectors are inside BAA scope (guide PDF text unreadable). https://help.openai.com/en/articles/8660679-how-can-i-get-a-business-associate-agreement-baa-with-openai ; https://help.openai.com/en/articles/20001069-hipaa-eligible-products-and-functionality (403, snippet only)
- **Implication for the rule:** neither vendor's BAA covers custom Claude connectors, and ChatGPT's coverage is unconfirmed. So "never to a cloud model" for clinical rooms must be enforced by Superyak itself (server-side per-room/place flag that refuses tool results), not by vendor settings.

## 4. Reference implementations (Python)
- Official MCP Python SDK `examples/servers/simple-auth`: separate AS (port 9000, with `/introspect`) and RS (port 8001), RFC 9728 + 8414. https://github.com/modelcontextprotocol/python-sdk/tree/main/examples/servers/simple-auth ; tutorial with full code: https://modelcontextprotocol.io/docs/tutorials/security/authorization
- SDK resource-server API: `MCPServer(token_verifier=..., auth=AuthSettings(issuer_url, resource_server_url, required_scopes, validate_token_resource))`; serves the 9728 doc and the 401 challenge; `get_access_token()` inside tools. Does NOT ship an AS (embedded one is legacy). Note this is the v2 SDK (`mcp>=2.0.0rc1`, release candidate). https://py.sdk.modelcontextprotocol.io/v2/run/authorization/
- FastMCP: `JWTVerifier` (tokens only), `RemoteAuthProvider` (needs a DCR-capable IdP), `OAuthProxy`/`OIDCProxy` (front an upstream IdP), full `OAuthProvider` (own AS, "avoid unless external providers can't meet your needs"). https://gofastmcp.com/servers/auth/authentication.md
- Fit for Superyak: the home already has logins, so it is its own AS. Smallest shape: Starlette routes for `/.well-known/oauth-protected-resource`, `/.well-known/oauth-authorization-server`, `/register` (or CIMD), `/authorize` (reuse existing login + consent), `/token` (form-encoded, S256, refresh rotation), plus a TokenVerifier. I found no small, well-regarded Python repo for exactly this; the examples above are the closest. Unverified.

## 5. Gotchas
- **Funnel is fine for DNS, but tailnet names are not:** Claude resolves the hostname first and rejects any non-globally-routable address, including CGNAT 100.64.0.0/10 (Tailscale IPs), mixed public/private answers, and AAAA-only hosts ("connectors are IPv4-only"). Use the public Funnel `*.ts.net` name. https://claude.com/docs/connectors/building/troubleshooting.md
- Funnel: ports 443/8443/10000 only; TLS only; non-configurable bandwidth limits; beta; disabled by default (needs `funnel` node attribute); new DNS can take ~10 min; repeated cert requests risk Let's Encrypt rate limits (up to 34 h). Certificates are publicly trusted (not self-signed). https://tailscale.com/kb/1223/funnel
- **A login "in front of everything" breaks discovery:** `/.well-known/*`, `/register`, `/token`, and `/mcp` must answer without the existing login (the MCP 401 must be a plain 401 + `WWW-Authenticate`, not a 302 to a login page). WAFs or auth proxies returning 403/302 are the top failure. Same for the authorization-server host. https://claude.com/docs/connectors/building/troubleshooting.md
- Redirects: a 3xx to another host makes Claude drop the Authorization header, producing "Authorization failed". Register the final URL. Same source.
- `resource`/`aud` mismatches (trailing slash, case, path) and issuer mismatches fail sign-in. Same source; ChatGPT: https://developers.openai.com/apps-sdk/build/auth
- DCR creates a new client per connection, so rate-limit and garbage-collect `/register`; unauthenticated DCR lets anyone register clients. https://claude.com/docs/connectors/building/authentication.md ; MCP tutorial pitfalls above.
- Pi latency: 10 s limit on token/registration endpoints; keep password hashing and I/O cheap.
- ChatGPT reports (community, unofficial, 2026): OAuth completes but no token forwarded; no re-auth after a 401; tool list frozen until Refresh; "OAuth state not found" callback 404s; some resolved on their own. https://community.openai.com/t/custom-mcp-connector-oauth-token-never-forwarded-401s-dont-trigger-re-auth-and-the-tool-list-is-frozen-per-publish/1400778 ; https://community.openai.com/t/chatgpt-mcp-connector-oauth-oauth-state-not-found-callback-fails-before-token-exchange/1378808
- Claude Team/Enterprise: an Owner must add the connector first; auth settings cannot be edited after adding (remove and re-add). https://claude.com/docs/connectors/custom/add-unlisted.md
- Not found: Funnel-specific connector bug reports; documented access-token lifetimes for either vendor (pick short, e.g. 1 h, plus rotating refresh).
