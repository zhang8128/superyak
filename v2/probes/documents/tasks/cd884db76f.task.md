When two machines pair, a person reads a short code off the exporting machine's own screen and types it on the other machine, so that the card in hand is compared with what that screen shows. I need the pieces for that code.

A card's code is the first 32 characters of the lowercase hex SHA-256 of the whole card in the fixed JSON form the program already uses for signing, including the person it identifies, so the same card gives the same code whatever order its keys come in, and changing any one field changes the code, including the identified person, network address and cryptographic identity. The card is checked first, and a card that fails that check, or something that isn't a card at all, gets no code and is refused the same way the check already refuses it.

For showing, the code is written in groups of four characters separated by single spaces. For reading back what someone typed, drop all whitespace and hyphens, including any at the ends, and lowercase it; the result counts only if it is exactly 32 ASCII hex characters, and otherwise there is no code. So 31 or 33 characters, a letter past f, a digit from another script such as an Arabic-Indic digit, or an empty entry all give no code, and input that isn't text at all, such as nothing, a number or a list, also gives no code rather than an error.
