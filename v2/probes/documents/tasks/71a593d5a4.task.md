Requests on the public route will soon pass through a filter that has to tell whether a request carries a real sign-in session or a real ship key before the route itself runs, and that filter must not leave any trace. Please give the station two yes-or-no reads for it.

The first says whether a session token is valid, doing the same lookup the ordinary sign-in check does: the session must exist and not have expired, and it must belong to a person, not a ship, who is not still waiting on activation. The second says whether a ship's key is valid, doing the same lookup as the ordinary finding of a ship by its key: the key must be known, not revoked, and belong to a ship. Each answers exactly true or false, and says false for every case that follows. Anything that is not a string, an empty string, a made-up value, or a ship key with an extra character on the end is not valid; a ship key longer than 128 characters is not valid without being looked up, and a long made-up session token is not valid either, like any other made-up one. A session token is never a valid ship key, nor a ship key a valid session. A ship key that has been revoked is no longer valid, and neither is a session once it has expired.

Neither read writes anything: no last-used time on a ship's key and no record of the ship being seen online, both of which the ordinary finding of a ship by its key writes. That ordinary lookup, and each route's own check that still runs afterwards, keep writing exactly as they do today.
