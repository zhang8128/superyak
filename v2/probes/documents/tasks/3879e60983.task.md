When the admin grants an owner trust, they should also say how many ships that owner may pair under it, and reaching that number should pause the trust.

Neither granting nor renewing a trust proceeds unless this ship count is supplied. It is a whole number from 1 to 10,000. Zero, a negative number, anything above 10,000, a fraction written as a decimal, true or false, text, or a supplied empty value is refused as a bad request (400) with a reason, and this is checked before the password, so a wrong password with a bad count still gets the 400. A grant or renewal refused for its count writes nothing. The count is recorded with the grant, and with each renewal; a revocation carries no count.

Each grant and each renewal opens its own window. A ship paired within the trust counts against the window of the latest grant or renewal, and each pairing records which window it counted in. If a trust allows two, the first and second ships pair, and the third is refused as too many (429), with an explanation of the pause. That refusal writes nothing at all, not even a mark against the day's cap, however many times it is tried. Only the administrator decides what happens next, by renewing the trust or revoking it in the browser. A renewal opens a new window with its own count, starting from none paired, while earlier pairings stay counted in their earlier window. A held ship that comes back under a later trust counts in that trust's window and uses its count.

The station should be able to show, for a trust, its current allowance of ships, which grant or renewal set it, and how much of it has been used; asking about a trust that does not exist is refused as not found (404). The daily cap of 200 pairings per trust stays exactly as it is, and still pairs only one of two attempts made at the same moment at the cap.
