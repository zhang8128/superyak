I'd like the station to be able to hand back a window of a room's messages by position, instead of always the whole room. Reading a room with no window asked for must stay exactly as it is today, byte for byte: nothing is added to it, and nothing in it says whether messages remain.

A client should be able to ask for a number of messages from 1 to 500, and the number is 100 when a window is asked for without one. With only a number, it gets the newest that many messages. It can also place the window in one of four ways: ending just ahead of an exclusive end position, beginning from an inclusive start position, beginning from a given message named by its id with that message included, or beginning just past a given message named by its id. Positions count from zero in the room's display order, the same order the full read gives, with messages relayed from a paired peer included; where a local message and a peer's message share an instant, today's order holds and the local one comes first. A client may also give an event-counter cursor, which is checked like the other numbers and counts as one of the ways to place a window, but what it picks is for a later change; for now a read with a valid one gives the newest, as a number alone does.

A windowed answer should let the reader tell that it is a window, and give the full-room count of messages, the position of the window's first message, and the counter of the room's latest message event, which is above zero once the room has messages. Everything else in it is the room-wide full read: the members, the brief and its revision, the active claims, and who the system's own messages come from whenever a system message is anywhere in the room, even outside the window. Each message carries its source and what it replies to, as in the full read. An empty room can be windowed too, with no messages, a full-room count of 0 and its first message's position given as 0.

Refuse as a bad request, and say why, when two or several ways of placing the window are given together; when a position, the number or the event-counter cursor is not plain digits making a whole number of zero or above, no longer than 15 digits; when the number is outside 1 to 500; when a message id is empty or longer than 100 characters; or when a position is out of range. An exclusive end position may run from 0 to the full-room count and an inclusive start position from 0 to one less than that count, and that refusal names the allowed range with the room's real numbers. A message id that is not in the room is answered as not found. Someone who is not a member gets the same not-found answer for a window as for the full read, and learns nothing new. Rooms read through a paired peer come back whole, as now.
