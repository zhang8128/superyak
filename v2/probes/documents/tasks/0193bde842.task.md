Only one process should ever be syncing a given data directory at a time. Give the program a way to take an exclusive hold on a data directory for syncing, through a lock file kept inside that directory. If the directory is already held, a second attempt must be refused at once rather than waiting, with an error explaining that the directory is in use. The hold lasts until its holder lets go of it or its process ends, and after that the directory can be held again.

When the server is started with syncing turned on, it should take this hold before it builds the app and keep it for as long as the server runs. If the directory is held elsewhere, the server should exit with status 1 and print why on its error output. Starting the server without syncing takes no hold, as now.

When the lock file is created, create it with permission 0600 so that only its owner can read or write it. Taking the hold must never follow a symbolic link: if the lock file turns out to be a link, taking the hold should fail with an error instead of locking whatever the link points to.
