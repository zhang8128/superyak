# Continuous Ollama Research Implementation Plan

> **For agentic workers:** Use the existing isolated worktree. Execute scoped tasks with behavioral tests; use parallel agents only for independent file ownership.

**Goal:** One command starts a resumable local literature researcher that adds sourced proposed claims and keeps running until stopped.

**Architecture:** Read-only Europe PMC and Ollama adapters feed a durable paper-job runner. A process controller exposes start/stop/status through the existing launcher. The runner records through ResearchInbox and renders its complete current publication bundle.

**Tech stack:** Python 3.11+ standard library; existing Store/ResearchInbox/Lighthouse/renderer; local Ollama; Europe PMC REST.

**Spec:** `docs/superpowers/specs/2026-09-07-ollama-research-design.md`.

## Adapter contract

`EuropePMC.search(query, cursor="*", limit=5)` returns `papers` (provider metadata) and `next_cursor` (string or null). `EuropePMC.read(paper)` returns `source` (portable source record), `passages` (nonempty objects with `id`, `locator`, `text`), `coverage`, `retrieved_at`, `content_sha256`, and `document_url`. Metadata includes a stable `key`, `doi`, and source citation. Full-text fallback is explicit. The exact retrieved passages are cached by the runner.

`Ollama(model, base_url="http://127.0.0.1:11434", timeout=120).check()` verifies the local model. `plan(question, context, prior_queries)` returns a nonblank query string. `extract(question, document, context)` returns `analysis` plus `metrics` and actual `model`. Analysis fields: `relevant` (boolean), `title`, `summary`, `scope`, `limitations`, `passage_id`, `quote`, `rationale` (strings). Relevant results require all strings nonblank. No citations, URLs, record IDs, status, or tool commands are generated by the model.

## Constraints

No legacy Atlas imports, database changes, automatic review promotion, peer messages, arbitrary model-selected URLs, automatic downloads, or grant renewal. Preserve source and capture provenance. Existing active question/view membership determines draft routing. The optional topic flag selects among configured questions; arbitrary archive topics require a separately configured inbox. Runtime state stays outside tracked artifacts.
