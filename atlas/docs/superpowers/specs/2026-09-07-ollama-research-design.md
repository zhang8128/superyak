# Continuous local literature research

Kairos asked for one command using the installed Ollama `qwen3.8:27b-mlx` model to pull research and add it to the graph, then specified that it should keep working until stopped. Begin with the active cell-fate/gene-regulation inbox. The cleaned archive remains a separate snapshot; this release does not silently put all 821 legacy topics into cell-fate publication views.

`atlas-research start` launches one detached local worker. `atlas-research stop` requests a graceful stop, and `atlas-research research-status` reports running state, current work, counts, last error, and the live HTML path. Repeating start does not launch another worker. Stop uses a local control file rather than signaling an unchecked PID. A foreground mode and finite cycle count support deterministic testing. The worker survives the calling terminal; it does not install login/reboot jobs.

The cycle selects an active question from the configured publication views, uses Qwen to propose a literature query, searches Europe PMC, fetches available open-access article text or explicitly labeled abstracts, and asks Qwen for one relevant, scoped, source-attributed claim. Source IDs and citations come from retrieval, never model output. A short verbatim excerpt must match a numbered retrieved passage. The model can decline relevance. Accepted claims become proposed drafts linked with `informs` to their question, preserving limitations, source coverage, retrieval hash, model identity, and run attribution. Schema/quote checks verify structure and provenance, not scientific truth.

Durable job files preserve fetched passages, model output, prepared drafts, and receipts before advancing the search cursor. Replays reuse the exact draft and stable worker session/idempotency key; a crash after capture cannot create another draft for the same job. Paper/target identity deduplicates repeat search results. Capture with pending publication remains saved and is recovered through refresh. Refresh/render failures must not be presented as successful publication. Invalid model output is recorded as an error and does not enter the graph; transient errors are retried with bounded delays.

Research state is under gitignored `.atlas/research/`; drafts and Lighthouse generations continue through `ResearchInbox`. The live HTML is derived from the current complete bundle, with no edits to the checked-in pilot, archive, or existing databases. One process lock enforces one worker per project. Requests have timeouts and bounded response sizes; source and model endpoints are fixed/read-only within their adapters. Default cadence pauses between passes and all-network failure backs off. Existing inbox capacity and policy expiry remain visible constraints, without automatic capacity changes or policy renewal.

Only installed local models are used; start checks availability and reports a missing model instead of initiating a large download. The observed local tag supports Ollama chat, `think: false`, and a JSON schema. Provider references: [Ollama chat](https://docs.ollama.com/api/chat), [structured outputs](https://docs.ollama.com/capabilities/structured-outputs), [Europe PMC developer services](https://europepmc.org/developers). A live API probe returned bibliographic records and abstracts; the record's actual coverage is always retained.

Validation: controlled HTTP responses for source/model adapters; real temporary inbox integration for capture/replay/publication recovery; subprocess lifecycle tests for duplicate start and graceful stop; one small live run inspected before leaving the authorized continuous worker running. Report the actual model, recorded IDs, elapsed timings, failures, start/stop commands, and live graph location.
