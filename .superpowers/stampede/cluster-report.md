# Remote bootstrap and Intel node workers

Implemented files: `deploy/stampede/bootstrap.sh`, `cluster.py`, `profiles.py`, and `engram/tests/test_stampede_cluster.py`. No commits or remote submissions were made.

## Interface and execution

- `bash ABS_RUN_DIR/source/deploy/stampede/bootstrap.sh ABS_RUN_DIR` reads `source/engram/uv.lock` and installs `.venv` using checksum-verified uv 0.8.3 and managed CPython 3.12.11. This operation is user-space and requires login-node Python 3, HTTPS access, and Linux x86_64. It performs no GPU operation or scheduler submission. Installation failures persist in `bootstrap-status.json`.
- `ABS_RUN_DIR/.venv/bin/python -m deploy.stampede.cluster batch --run-dir ABS_RUN_DIR` requires config.json and a Slurm allocation with exactly one task per node. Sources must be on PYTHONPATH (`source:source/engram`). It launches node workers with `ibrun` and `TACC_TASKS_PER_NODE=1`.
- Slurm end time comes from `SLURM_JOB_END_TIME` or bounded `scontrol show job -o`. Work stops 240 seconds before expiry; batch permits 150 seconds for workers to finish snapshots before killing the launcher group. Worker ranks come from PMI_RANK, PMIX_RANK, or SLURM_PROCID. Per-host advisory locks reject duplicate node owners. Worker reports carry the Slurm job_id; once failure/partial status is durably written, the worker exits zero so Intel MPI cannot abort unrelated ranks because of an expected branch failure. Batch alone returns nonzero for partial/failed campaigns, ignores prior-job node reports, requires a successful launcher exit for completion, and refreshes current-job node/hardware verification summaries at most once per second during execution. LocalModel uses the configured campaign seed (default 20260912), matching the experiment cells.
- Live stores reside under fresh `/tmp/superyak-JOB-RANK-*` directories. Experiment-owned consistent SQLite snapshot generations and result.json live in `cells/CELL/`. Comparison cell_seconds remains the configured cumulative budget across resumes; session_seconds independently clips each invocation to allocation time remaining, so a short allocation cannot silently change total cell allowance. The scheduler uses a separate scheduler.lock and scheduler.json; interrupted node-local directories can disappear safely because experiment restoration uses complete durable generations.
- Comparison cells are shuffled reproducibly using the cell seed before rank assignment, avoiding simple product-order/rank grouping. With multiple nodes, rank zero owns the community while other nodes rotate comparisons. One node interleaves 60-second community epochs between comparison cells. Community identity stays fixed at max_turns=1000/max_calls_per_cell=1,000,000, with a cumulative 86,400-second ceiling and a per-session deadline. Resumes preserve identities and memory. Community budget exhaustion is annotated `epoch_limit`, `allocation_limit`, or `cell_budget`; it is not reported as completed research.

## Independent Intel profiles

Each node runs vLLM and SYCL preparations/probes independently and concurrently, each bounded to at most 2700 seconds (or remaining allocation time). They retain separate node logs and result JSON even if one fails. Shared profile installation is serialized by advisory locks, so one node builds each profile and the others reuse it. Backend selection requires both a passed branch and actual local server chat inference. If a passed branch fails server startup, another passed branch can be attempted before campaign selection. The first successful chat fixes `campaign-backend.json` under a shared lock (backend/source/model revision, dtype, device selector). Subsequent nodes use that same selection; incompatible nodes fail independently. Alternate successful inference remains a diagnostic and cannot silently enter the matrix. Each cell records and validates its inference identity, hostname, and device-probe log; different-backend resume is rejected. The experiment receives the resolved model SHA in its resume identity. Explicit backend configuration filters selection but both probes are still retained.

- vLLM source commit: `13e221f8308416564a446909c2fd4805c78fbb8a`. Its upstream XPU requirements pin torch 2.13.0, triton 3.7.2+xpu, and vllm_xpu_kernels 0.1.14.1. Build ninja is pinned to 1.11.1.4. Source, Python version, generated dependency lock with package hashes/index URLs, and installed package freeze are retained. The profile requests XPU source installation without build isolation or dependency replacement after syncing its lock.
- llama.cpp source commit: `3057bb66c86c46d5781e50e85462a760ba7d1feb`. CMake 3.31.6 and Ninja 1.11.1.4 are pinned; converter requirements come from that immutable source and resolve into a hash-bearing lock. The SYCL build requires site-provided icx/icpx, sycl-ls and oneAPI libraries (PATH or `/opt/intel/oneapi/setvars.sh`). Compiler version and built server SHA256 are recorded. Missing site components fail this branch independently. No root operation, kernel-driver change, or unverified compiler download is attempted.
- The vLLM probe actually allocates and multiplies XPU tensors, synchronizes, checks the result, and reports visible device properties and package versions. SYCL checks Level Zero enumeration and llama-server device discovery. Both print kernel/OS information. Actual model server inference remains a separate required gate: it receives the exact experiment SYSTEM prompt and a small synthetic source packet, and must pass experiment._validate_output with answer/memory/publication plus publication.action=none. Plain text and malformed structured completions cannot accept the campaign backend. Successful startup response/decision/usage is retained in the node inference diagnostic.
- Servers bind only 127.0.0.1 and use one visible Level Zero device (`ONEAPI_DEVICE_SELECTOR=level_zero:0`), conservative tensor parallelism 1, model context 8192 per slot, and maximum configured concurrency. This is an initial correctness deployment, not verified four-GPU/node utilization. vLLM uses bf16 and eager mode; SYCL converts the same pinned HF snapshot into f16 GGUF and records the converter and derived SHA256. Served model name/alias matches config.model.
- Main HF revision is resolved once into `model/resolved.json` before snapshot download. Retries preserve that revision. `model/manifest.json` records every downloaded model file's SHA256 and size. No model Python is downloaded or executed. Local servers operate with HF offline mode; the model download process is independently bounded.

## Verification and practical limits

The initial 11 tests failed before implementation. Additional failing regressions caught orphan process groups, experiment status names, directory ownership, community scheduling, structured startup acceptance, cumulative versus session budgets, handled MPI worker failures, stale job reports, launcher failures, and live verification summaries. Latest component run: **31 focused cluster tests passed** (experiment follow-up work is separately verified by its owner); shell syntax checked with `bash -n` and owned Python modules compiled. Tests run actual child processes for independent failure/timeout behavior, server/grandchild cleanup, bootstrap failure persistence, and actual Engram storage/checkpoint restoration through the scheduler. GPU/site/network calls are boundaries; no Intel environment or model was installed locally.

No TACC allocation, host driver, Intel wheel resolution/build, compiler environment, inference capacity, model conversion, or distributed launcher behavior has been tested on actual hardware. Source profiles are immutable, but transitive package resolution occurs on first compute setup and its precise lock is retained for reproducible retries. Long first builds may exceed the bounded setup budget and will be reported as failed/timed out. Site oneAPI availability determines whether the SYCL branch can build. Snapshot time and remaining outstanding HTTP calls must fit the shutdown reserve; Slurm can always force termination, leaving the last complete snapshot authoritative.
